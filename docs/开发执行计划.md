# 周报软件自主迭代执行计划

## 目标与推进方式

依据[开发任务计划](./开发任务计划.md)和[三阶段开发计划](./三阶段开发计划.md)，从项目骨架持续迭代至 Windows 首版。每个功能切片按“实现、定向测试、修复、复测、更新状态”推进；阶段内独立任务可并行，阶段验收通过后再以其成果作为下一阶段基座。

遇到必须由用户决定的需求、外部授权或不可自行准备的环境时记录阻塞并处理本阶段其他无阻塞事项；模拟测试不能替代真实服务验收。开发过程中保留用户数据和未提交修改，不自动提交、推送、升级数据库或发送真实工作内容。

## 已确认的实施规则

- **界面和运行：**Windows x64、.NET 10、WPF 和 Fluent 风格；主题及强调色跟随系统。关闭主窗口时隐藏到托盘，托盘菜单提供退出，自启动默认关闭。
- **数据库：**使用本机 MySQL 8.0.46，SqlSugar 负责业务访问，DbUp 版本化 SQL 负责结构变更；应用不安装或升级 MySQL。数据库密码和 DeepSeek API Key 使用当前用户 DPAPI 保护。
- **工作项：**用户配置本地 Git 仓库及各项目作者，手动同步当前 `HEAD` 可达提交；按项目与本地日期生成可编辑描述，提交按项目及完整哈希去重。重复同步不覆盖已编辑描述或已确认工时。
- **工时：**使用作者时间，同项目同日相邻提交间隔不超过 2 小时才形成候选区间；单次提交不能推断。跨项目重叠区间平均分摊，自动估算每日合计最多 8 小时；人工可修改并确认，超过 8 小时提示但允许保存。
- **周报：**周一至周日为一周，每周一份，包含本周工作、下周计划、问题与风险及工时汇总；已有周报和未保存编辑不被重复生成静默覆盖。
- **AI：**用户主动调用 DeepSeek，默认模型 `deepseek-flash`；发送前确认内容，结果预览后自行应用并显式保存，可选润色 Git 工作项。
- **导入导出：**JSON 全量业务备份；Excel 支持单周或多周汇总，包含周报、对应工作记录、关联项目、提交来源和工时；Markdown 用于单篇阅读导出。按稳定标识去重，导入默认跳过冲突，用户确认后可覆盖，失败事务回滚。
- **提醒：**每周四 17:00、周五 10:00 各提醒一次，即使周报已保存；恢复运行时只补发错过不超过 2 小时的提醒。应用退出、关机或休眠期间不保证准点提醒。

## 工时计算口径

1. 将提交的作者时间转换为系统本地日期，同项目同日按实际时间排序；相邻提交间隔不超过 2 小时的区间才参与估算，不跨本地日期。
2. 依据当天全部已导入项目和本次同步预览的候选区间，以区间边界拆分重叠时段；每段在覆盖它的项目之间平均分摊。
3. 当候选区间并集超过 8 小时时，各项目自动建议值按比例压缩，使每日合计为 8 小时；统一舍入并保持项目值之和与每日总数一致。
4. 区分估算、用户确认或修正；重算只提出建议，不静默覆盖已确认工时。单次提交显示无法推断，不代表实际没有工作。

示例：A 为 09:00—10:00，B 为 09:30—10:30；两项目各分得 45 分钟，当日估算总计 90 分钟。

## 阶段任务与交付

| 阶段 | 主要任务 | 基座和可交付成果 | 验收门槛 |
| --- | --- | --- | --- |
| 一：桌面与数据 | 建立 .NET 解决方案、WPF 桌面与托盘、主题、MySQL 配置、SqlSugar 映射、DbUp 迁移及工作记录 | 可运行的桌面开发版、源码、迁移和基础测试 | 构建通过；托盘、悬浮窗、主题及隔离 MySQL 增删改查和故障反馈通过 |
| 二：Git 与周报 | 实现本地 Git 同步、工时估算、周报历史、DeepSeek 和 JSON/Excel/Markdown 交换 | 可生成和编辑工作项、工时及周报的功能版，含 Excel 模板和测试 | 临时 Git 仓库、工时边界、真实 MySQL 事务、文件往返及经授权的 DeepSeek 调用通过 |
| 三：提醒与发布 | 实现两次定时提醒、去重与补发、通知激活、安装包、升级卸载和使用文档 | Windows x64 安装包、自包含发布产物、用户文档和验收结果 | 通过提醒边界、系统通知、完整业务流程和干净 Windows 安装验证 |

### 第一阶段迭代

1. 同步已确认的计划、建立解决方案和分层项目，核实 .NET、SqlSugar、DbUp、托盘及 Windows 通知的兼容性。
2. 建立主窗口、悬浮窗、托盘、单实例、系统主题与基础控件，支持键盘焦点和常见缩放。
3. 实现数据库连接设置、DPAPI 凭据保护、版本化迁移、工作记录及异步持久化；新库和升级使用隔离测试库验证。
4. 验收桌面行为、数据库异常与持久化；不足条件的真实验证明确标记，不声称通过。

### 第二阶段迭代

1. 配置多个本地仓库及作者，使用参数列表只读 Git；预览提交和按项目/日期生成的工作项，处理路径、进程失败和重复同步。
2. 实现工时建议、重叠分摊、每日封顶、用户确认和修改；项目 A 的 09:00—10:00 与项目 B 的 09:30—10:30 必须分别得到 45 分钟。
3. 实现周报草稿、周唯一约束、历史及快照；可选通过 DeepSeek 润色工作项或周报，发送前确认。
4. 实现 JSON 全量备份和 Excel 单周/多周交换。Excel 模板包含“格式信息”“项目”“工作记录”“Git提交来源”“周报”；备份不含本机仓库绝对路径、作者匹配配置或凭据，导入后可重新绑定仓库。
5. 校验版本、结构、日期、公式及大小限制，预览冲突后使用同一 SqlSugar 事务导入；验证往返、重复导入、覆盖和中途失败回滚。

### 第三阶段迭代

1. 用可注入时钟实现周四和周五的本地时间调度，重启、唤醒及时间变化后重算；使用本地受保护状态按“周 + 提醒类型”去重，不依赖 MySQL。
2. 验证 2 小时补发边界、数据库断连、通知不可用及点击后打开对应周报。
3. 构建 `win-x64` 自包含发布和 Inno Setup 安装包，编写配置、Git、工时、备份恢复和故障排查文档。
4. 在可用的干净 Windows 环境验证安装、升级、卸载与完整使用流程；缺少授权或环境时记录具体阻塞。

## 验证与安全约束

- Git 测试使用临时仓库和虚构提交，不修改用户现有仓库；DeepSeek 真机验证须经用户授权并使用非敏感数据。
- 数据库集成测试使用独立测试库，只清理由测试明确创建且确认隔离的数据；MySQL DDL 存在隐式提交，迁移不能承诺整体回滚。
- JSON 和 Excel 包含明文业务数据；不导出数据库凭据、API Key、原始 AI 请求或响应、本机仓库路径及作者匹配配置。
- 不执行 Excel 公式、宏或外部链接；文本按文本单元格输出，超限时明确失败而非截断。
- 代码和文档更新后执行相关定向测试及阶段验收；外部服务、系统通知和安装环境无法验证时，不把模拟结果作为最终验收。
