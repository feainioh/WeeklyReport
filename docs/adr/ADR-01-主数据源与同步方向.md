# ADR-01 主数据源与同步方向：SQLite 本地优先 + 双向安全同步（A1）

状态：已接受（Phase 0，2026-11-03）

## 背景

《离线可用与本地优先存储计划》§3.1 要求在 A1（本地优先 + 双向同步）/ A2（SQLite 主库 + 单向镜像）/ A3（MySQL 主库 + 只读缓存 + 写队列）之间以 spike 证据决策。

## 决策

采用 **A1**：SQLite 本地优先工作副本 + MySQL 双向安全同步（无冲突自动合并，冲突进用户处理）。

## 依据（spike 证据，2026-11-03）

MySQL 侧同步最小闭环 5/5 通过（隔离库 `weeklyreport_test_spike`）：

1. 同操作组 ID 重试幂等（响应丢失场景不重复写入）；
2. 同 ID 内容哈希不一致拒绝重放（硬错误）；
3. 事务内基线比较能识别并发修改（冲突信号，不写入）；
4. 业务失败时回执不落库（业务 + 回执同 InnoDB 事务原子提交）；
5. 行锁等待超时（会话级 `innodb_lock_wait_timeout=3`）报错可重试，锁释放后同 ID 重试成功。

## 后果

- Phase 1–2 按计划 A1 路径实施：本地事务 + `sync_operation` 入队、MySQL 回执表、后台同步协调器、三方比较与冲突。
- 若 Phase 2 实施中发现无法证明安全的场景增多，回退选项 A2/A3 仍有效；本 ADR 随之修订。
- 诚实边界：真实进程崩溃注入未执行；"本地确认前崩溃"以同 ID 重试幂等（第 1 项）等价覆盖，Phase 2 需补真实崩溃恢复测试。
