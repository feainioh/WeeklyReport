# 周报软件三阶段开发计划

## 1. 计划说明

本计划将[原开发任务计划](./开发任务计划.md)拆分为三个递进阶段，每个阶段均形成可运行、可验证的成果。需求细节、数据规则和异常处理以原计划为准；原计划中的建议默认值，尤其是周报周期、错过提醒补发和导入冲突策略，仍需在相关功能开发前确认。

| 阶段 | 目标 | 阶段产出 | 原计划任务对应 |
| --- | --- | --- | --- |
| 第一阶段：桌面与数据基座 | 建立可常驻的桌面应用及本地数据能力 | 可运行的桌面应用和工作记录管理功能 | 原阶段 0～3 |
| 第二阶段：周报与数据交换 | 打通周报编写、DeepSeek 辅助生成和导入导出 | 可编写周报、查询历史及备份恢复的功能版本 | 原阶段 4、6、7 |
| 第三阶段：提醒与正式交付 | 完成定时提醒、系统集成和全流程验收 | 可安装、可使用的首版发布包及文档 | 原阶段 5、8 |

阶段顺序为**第一阶段 → 第二阶段 → 第三阶段**。每阶段验收通过后再以该阶段成果为下一阶段基座；阶段内相互独立的任务可并行。具体工期在规则确认和技术验证后估算。

## 2. 第一阶段：桌面与数据基座

### 2.1 目标

构建可在 Windows 上启动并驻留托盘的应用，完成悬浮窗、基础界面和本地 MySQL 连接，让用户能够维护工作记录。

### 2.2 开发基座与前置条件

- **输入基座：**原开发计划、已选定的技术栈和 Fluent 界面方向；项目 Git 仓库为 `https://github.com/feainioh/WeeklyReport.git`。
- **技术基座：**C#、.NET 10 LTS、WPF、CommunityToolkit.Mvvm、MySQL 8.4 LTS、MySqlConnector、Dapper、DbUp、Windows DPAPI、Serilog 和 xUnit。
- **环境条件：**准备 Windows x64 开发环境和可连接的本机 MySQL；数据库账号由用户配置，不将密码写入源码、日志或示例文件。
- **待确认条件：**确认工作记录字段和周起止规则；其他规则须在其所属阶段实现前确认。

### 2.3 开发任务

1. **需求与技术验证**
   - 明确首版范围及工作记录规则，建立主要界面原型。
   - 验证 WPF 悬浮窗、托盘、Windows 通知注册与点击激活、系统唤醒事件、MySQL 迁移，以及 DeepSeek 接口和自包含安装方案的可行性；通知调度、AI 功能和安装包在后续阶段正式实现。
   - 确认并锁定兼容的依赖版本；记录验证结论和环境要求。
2. **工程与通用能力**
   - 建立解决方案、界面层、应用服务层、数据访问层和测试项目；配置构建、日志、异常提示和单实例控制。
   - 建立 Fluent 风格主题和基础控件，支持跟随系统浅色、深色、强调色及高对比度；保证键盘焦点和常见缩放比例下可用。
3. **桌面常驻**
   - 实现悬浮窗展示、拖动、置顶、收起、位置保存及屏幕外位置恢复。
   - 实现托盘菜单、主窗口显示与隐藏、退出和可选自启动；明确关闭窗口与退出程序的区别。
4. **数据基座与工作记录**
   - 实现本机 MySQL 配置、连接检查、DPAPI 凭据保护、版本化 SQL 迁移和错误反馈；数据库操作异步执行。
   - 建立工作记录表及稳定业务标识，实现新增、修改、删除和按周查询；为第二阶段的周报与导入导出准备可迁移的数据结构。
   - 失败时保留当前输入并提示用户，不将未持久化内容标记为已保存；日志不记录密钥或业务正文。

### 2.4 可交付产出

- 可启动的开发版应用：包含主窗口、悬浮窗、托盘和工作记录管理。
- 工程源码、构建配置、锁定的依赖信息、数据库迁移脚本和基础测试。
- 开发环境及本地 MySQL 配置说明、界面原型和关键技术验证结果。
- 为后续阶段提供稳定的应用分层、主题组件、数据访问、凭据保护及日志基座。

### 2.5 阶段验收与完成条件

- 应用可启动、隐藏到托盘、恢复和退出；悬浮窗可拖动、收起，重启后位置有效，多显示器变化后仍可找回。
- 系统浅色、深色及强调色切换可反映到界面；高对比度、键盘焦点和常见缩放下主要操作可读、可用。
- 连接本地 MySQL 后，工作记录可增删改查，重启应用后仍可查询；数据库不可用或认证失败时有明确提示。
- 新库迁移与已有库升级均可验证；基础单元测试和真实 MySQL 集成测试通过，记录技术验证中未解决的问题。

## 3. 第二阶段：周报、DeepSeek 与数据交换

### 3.1 目标

在第一阶段基座上形成完整的周报编写流程，支持 AI 辅助生成、历史查询以及 JSON、Excel 导入导出。

### 3.2 开发基座与前置条件

- **输入基座：**第一阶段已验收的桌面应用、工作记录、MySQL 数据访问、迁移机制、主题和凭据保护能力。
- **技术基座：**DeepSeek 官方 API、`HttpClient`、`System.Text.Json` 和 ClosedXML；数据库继续使用第一阶段技术栈。
- **待确认条件：**确认周报模板和字段、周周期、重复生成行为、导入冲突策略及 AI 发送内容；在用户授权并提供密钥后开展真实 DeepSeek 接口验证。

### 3.3 开发任务

1. **周报与历史**
   - 增加周报数据表及迁移，按周汇总工作记录生成草稿，支持编辑本周工作、下周计划、问题与风险并显式保存。
   - 实现历史列表、查看、修改和二次确认删除；每周一份周报，重复生成不静默覆盖已有编辑。
   - 已保存周报作为独立快照，后续工作记录变化不自动覆盖；保存失败时保留当前输入并明确提示。
2. **DeepSeek 辅助生成**
   - 使用官方 HTTPS 对话接口，支持用户配置模型和 API Key，默认模型为 `deepseek-flash`；用 DPAPI 保护密钥。
   - 用户主动发起并确认发送内容及服务目标；展示生成、取消、结果预览和错误状态。结果须由用户确认应用并显式保存，不静默覆盖现有内容。
   - 覆盖认证失败、余额不足、限流、超时和无效响应；失败时保留原内容，可继续手动编辑。提示可能产生费用，不记录密钥、请求正文或返回正文。
3. **数据导入导出**
   - 实现带版本的 JSON 和 Excel `.xlsx` 全量业务数据导出、导入；Excel 提供格式信息、工作记录和周报工作表及导入模板。
   - 实现单篇周报 Markdown 导出；明确 Markdown 仅供阅读，不用于数据恢复。
   - 校验格式版本、字段、日期、周周期、文件内重复项和 Excel 工作表、列及单元格；拒绝业务数据单元格公式，导出文本按文本类型写入，超出 Excel 限制时明确报错，不截断。
   - 预览导入数量与冲突，默认跳过已有数据，用户可选择覆盖或取消；用户确认后以数据库事务导入，失败整体回滚并报告结果。
   - 导出不包含数据库凭据、API Key、AI 配置或提醒去重状态；提示备份文件包含明文业务数据。

### 3.4 可交付产出

- 可运行的功能版本：支持工作记录、周报编写与历史、DeepSeek 生成及数据导入导出。
- 周报迁移脚本、DeepSeek 配置与调用实现、JSON/Excel 格式定义及 Excel 导入模板。
- 周报、AI 和导入导出测试，以及格式使用、冲突处理和备份说明。
- 为第三阶段提供可从提醒直接打开的周报入口及完整业务流程。

### 3.5 阶段验收与完成条件

- 同一周重复生成不会静默覆盖已编辑内容；保存后重启可查看历史；修改工作记录不会静默改变已保存周报。
- 模拟 DeepSeek 成功和各类失败，验证发送前确认、密钥保护、结果预览及显式保存；使用用户授权的密钥和非敏感数据完成一次真实调用。
- JSON 和 Excel 各自完成多周数据导出到空库再导入的逐字段核对；重复导入验证跳过和覆盖，错误文件及中途失败不得造成部分写入。
- 验证 Excel 模板、缺列、错误单元格、公式、超限文本和公式符号开头文本；备份不含凭据，Markdown 可正常阅读。
- 相关单元测试、真实 MySQL 集成测试及主要页面人工验证通过。

## 4. 第三阶段：定时提醒与正式交付

### 4.1 目标

在完整周报流程上实现可靠的桌面提醒，完成全流程测试、安装发布和用户文档，交付首版可安装软件。

### 4.2 开发基座与前置条件

- **输入基座：**第二阶段已验收的周报入口、历史数据、桌面常驻、配置及日志能力。
- **技术基座：**Windows App SDK 通知、Windows Forms 托盘、`.NET TimeProvider` 与计时器、系统事件、`dotnet publish` 和 Inno Setup。
- **待确认条件：**确认周四及周五提醒是否因已保存而跳过、错过后的补发窗口、自启动默认值和通知不可用时的提示方式。

### 4.3 开发任务

1. **定时提醒与状态管理**
   - 按系统本地时间在每周四 17:00、周五 10:00 分别触发提醒，支持点击通知打开对应周报或生成入口。
   - 应用启动、系统时间或时区变化及唤醒后重新计算调度；按确认后的规则补发错过的提醒。
   - 以“周 + 提醒类型”去重；提醒状态保存在受当前用户保护的本地应用数据中，避免 MySQL 断连导致无法提醒；状态读写失败时明确提示。
   - 利用单实例机制防止重复调度，验证托盘状态、重启和唤醒；通知权限关闭或通知不可用时给予明确提示。
2. **可靠性、安全与体验**
   - 完成异常路径和端到端测试：MySQL 断连、DeepSeek 错误、导入回滚、通知不可用、主题变化及多显示器场景。
   - 检查密钥保护、日志及导出内容，补充必要的故障诊断和可操作提示。
3. **发布与文档**
   - 构建 `win-x64` 自包含发布包及 Inno Setup 安装包，处理 Windows App SDK 运行时、通知注册和卸载清理。
   - 编写安装、MySQL 配置、DeepSeek 配置、日常使用、导入导出、升级卸载、MySQL 备份恢复及故障排查文档。
   - 在干净 Windows 环境验证安装、运行、升级和卸载，并说明卸载后数据库及用户数据的保留情况。

### 4.4 可交付产出

- 首版 Windows x64 安装包和自包含发布产物。
- 可从工作记录、周报、AI 生成、提醒到数据备份恢复贯通的完整应用。
- 用户使用及运维文档、测试结果、已知问题和版本说明。
- 定时调度、通知激活、安装升级及卸载清理的实现与测试。

### 4.5 阶段验收与完成条件

- 使用可注入时钟验证周四 17:00 和周五 10:00 两次提醒独立触发；托盘运行、时间变化、重启和唤醒符合已确认的去重与补发规则。
- 数据库断连时提醒仍可触发；点击提醒可进入对应周报；通知禁用和本地状态不可写时有明确反馈。
- 在干净 Windows 环境按文档完成安装、连接 MySQL、录入记录、生成并保存周报、调用 DeepSeek、触发提醒及 Excel/JSON 导入导出。
- 全量相关测试通过；验证升级、卸载及手动数据库备份恢复，安装包和文档可交付。

## 5. 跨阶段约束

- **提醒边界：**应用运行或在托盘后台运行时才能自行调度；关机、休眠或完全退出期间不保证准点提醒，恢复后按最终确认的规则补发。若要求应用未运行时也提醒，需要另行设计任务计划程序集成。
- **数据安全：**数据库密码和 DeepSeek API Key 不写入源码、日志或导出文件；AI 调用需用户确认，文件导出提示明文业务数据风险。
- **数据持久化：**MySQL 是历史数据的持久化来源；未成功保存的数据不显示为已保存。数据库迁移需考虑 MySQL DDL 隐式提交，不能承诺迁移整体可回滚。
- **发布范围：**首版不自动安装 MySQL；仅支持应用导出或符合模板的 `.xlsx` 导入，不默认支持任意 Excel 表格、`.xls` 或含宏工作簿。
- **范围控制：**多人协作、跨设备同步、更多导出格式和应用内自动备份留待后续确认。
