### B. 需用户确认：唯一数据源和迁移方向

这是后续架构工作之前的范围门槛，当前未决定：

- **选项 1：SQLite-only。** 需确认应用定位为单用户/单台设备，不再要求多设备共享或远程集中数据库；并确认是否需要将现有 MySQL 中的数据迁入 SQLite。
- **选项 2：保留 MySQL + SQLite 本地优先。** 继续保留 MySQL 实现、同步协议和 MySQL 验收；需准备隔离测试库进行端到端验收。

若选择 SQLite-only，实施前还需确认：

1. 现有 MySQL 数据是否必须迁移；建议只读导出/迁移，校验完成前保留 MySQL 原库，不做删除或覆盖。
2. Git 项目本机绑定（仓库路径、作者筛选）是否必须迁移。通用业务备份未必包含这些本机专属配置，应单独核实和设计。
3. 是否接受失去多设备/远程数据库共享能力，以及 SQLite 文件和独立备份由用户自行保护。
4. SQLite-only 版本中是否完全移除旧同步队列、同步身份/冲突状态，还是先保留以兼容升级中的未同步数据。

**解除门槛所需回答：** 选择“SQLite-only”或“保留 MySQL + SQLite”；若选 SQLite-only，再回答是否迁移 MySQL 数据及 Git 本机绑定、是否接受单机定位。未确认前只做不改变后端范围的审计与修复。
