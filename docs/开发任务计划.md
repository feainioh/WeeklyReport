# 桌面周报软件开发任务计划

项目 Git 仓库：[feainioh/WeeklyReport](https://github.com/feainioh/WeeklyReport.git)

## 1. 项目目标与范围

开发一款以 Windows 桌面为首要目标的个人周报工具：通过桌面悬浮窗或系统托盘常驻，每周四 17:00、周五 10:00 提醒用户整理周报，并将周报及历史数据保存到本机 MySQL。

首版支持手动录入、汇总和编辑，也支持用户配置 DeepSeek API Key 后主动使用 AI 辅助生成周报，并提供本地数据导入导出。多人协作和跨设备同步暂不纳入首版。

### 首版交付

- 可打开、收起、拖动的悬浮窗，以及最小化到系统托盘、恢复和退出。
- 日常工作记录、按周生成周报草稿、编辑和保存。
- 使用用户配置的 DeepSeek API Key 生成或润色可编辑的周报草稿。
- 两个固定时间的桌面提醒，支持点击提醒打开对应周报。
- 本地 MySQL 配置、连接检查、建表迁移和历史周报查询。
- 通过 JSON 或 Excel 导出、导入工作记录和历史周报，支持可读周报导出。
- 安装、启动、配置、升级和故障排查文档。

## 2. 产品规则与待确认事项

下列规则是开发估算和验收的**建议默认值**，正式实现前需要确认；未确认项不应被当作既定业务要求。

| 事项 | 建议默认值 | 待确认 |
| --- | --- | --- |
| 运行平台 | Windows 10 22H2 或 Windows 11，x64；单用户桌面应用 | 是否需要 ARM64、macOS 或其他版本；Windows 10 需关注系统支持和安全更新 |
| 周期 | 本地时间周一 00:00 至下周一 00:00，周报标注该周起止日期 | 是否使用其他统计周期 |
| 周报内容 | 本周工作、下周计划、问题与风险；可从本周工作记录手动汇总或经 AI 生成可编辑草稿 | 模板、字段和 AI 提示词 |
| 重复生成 | 每周一份周报；已有周报时打开原周报，不覆盖用户编辑内容 | 是否允许同一周多个版本 |
| AI 服务 | 首版固定接入 DeepSeek 官方 API；用户配置 API Key 和模型，每次手动发起 | 是否需要支持其他模型或服务商 |
| AI 数据发送 | 调用前展示将发送的内容和目标服务，用户确认后才发送 | 是否需要脱敏、数据留存提示及其他合规要求 |
| 提醒 | 周四 17:00 和周五 10:00 各提醒一次，即使周报已保存也提醒 | 已完成周报是否跳过周五提醒；是否允许用户调整时间 |
| 错过提醒 | 应用重新运行或电脑唤醒时，仅补发距离计划时间不超过 2 小时的提醒；同一时间点不重复提醒 | 补发窗口和免打扰规则 |
| 自启动 | 安装后可由用户选择开启，默认关闭 | 是否要求默认开启或必须在应用退出时也能提醒 |
| 导入导出 | 使用带版本的 JSON 或 Excel（`.xlsx`）导出和导入全部业务数据；周报可另存为 Markdown 阅读文件 | 是否增加 Word 或 PDF、按时间范围导出，以及导入自定义 Excel 表格 |
| 导入冲突 | 预览冲突，默认跳过已有数据；用户可明确选择覆盖或取消 | 是否需要更细的逐条合并策略 |
| 数据删除 | 支持查询、编辑和明确确认后的删除 | 是否需要软删除及应用内自动备份 |

**提醒边界：**应用正常运行或在托盘后台运行时才能自行调度提醒；电脑关机、休眠或应用完全退出期间不能保证准点提醒。恢复运行后按上述待确认规则补发。若要求应用未运行时也提醒，应单独设计 Windows 任务计划程序集成和权限、安装及卸载流程，而不是承诺仅靠托盘常驻实现。

## 3. 确定的开发技术栈

以 Windows 单用户桌面应用为首版目标，采用以下技术栈；尚未确定的业务规则仍按第 2 节处理。

| 层面 | 技术选型 | 用途和约束 |
| --- | --- | --- |
| 语言与运行时 | C#、.NET 10 LTS，目标框架 `net10.0-windows` | Windows x64 桌面应用；.NET 10 支持至 2028-11-14 |
| 桌面界面 | WPF + CommunityToolkit.Mvvm | MVVM 实现主窗口、悬浮窗、数据绑定和异步命令 |
| 托盘与通知 | Windows Forms `NotifyIcon` + Windows App SDK `AppNotificationManager` | 托盘菜单及原生通知、点击激活；托盘生命周期由 WPF 应用管理 |
| 定时调度 | .NET `TimeProvider`、计时器和 Windows 系统事件 | 计算本地时间触发点、唤醒与时间变化后的重算；注入时钟便于测试，不依赖数据库调度 |
| 数据库 | 本机 MySQL 8.4 LTS，InnoDB、`utf8mb4` | 保存工作记录和历史周报；MySQL 单独安装与运行 |
| 数据访问 | MySqlConnector + Dapper | 异步、参数化 SQL 和事务；避免将界面与数据库耦合 |
| 数据库迁移 | DbUp + `dbup-mysql`，使用版本化 SQL 脚本 | 创建和升级表结构，记录已执行迁移；迁移包依赖 MySqlConnector，需统一兼容版本 |
| AI 接入 | DeepSeek 官方 API + .NET `HttpClient` + `System.Text.Json` | 调用 DeepSeek 的 OpenAI 兼容对话接口；使用官方服务地址，模型和 API Key 由用户配置 |
| 数据交换 | ClosedXML、`System.Text.Json` | 读写 `.xlsx` 和 JSON，不要求安装 Excel；Markdown 用 UTF-8 文本输出 |
| 凭据与配置 | Windows DPAPI（当前用户范围）+ 本地配置文件 | 保护数据库密码和 API Key；普通配置不含明文密钥，密钥不进入版本库或导出文件 |
| 日志 | Serilog 文件日志，按大小或日期滚动 | 记录必要诊断信息，不记录密钥或业务正文 |
| 测试 | xUnit + 可注入时钟与模拟 HTTP；真实 MySQL 集成测试 | 验证业务、调度、AI 异常及数据库事务；Windows 通知等另做人工端到端测试 |
| 发布 | `dotnet publish` 自包含发布 + Inno Setup 安装包 | 目标 `win-x64`；安装时处理 Windows App SDK 运行时及通知注册要求，不自动安装 MySQL |

**版本管理：**首版固定上述主要技术及 .NET/MySQL 主版本；各 NuGet 包、Windows App SDK 和安装工具在项目创建时选用相互兼容的稳定版本并锁定，在技术验证通过后记录精确版本，不预先假定所有最新版本兼容。

**实现边界：**WPF 与 Windows App SDK 的通知注册、点击激活和卸载清理，以及自包含发布所需运行时必须在阶段 0 实机验证。应用关闭后不承诺按时提醒；数据库迁移需考虑 MySQL DDL 的隐式提交，失败时明确报告并提供修复或重试步骤，不能将迁移整体视作可回滚事务。

**架构：**界面层（悬浮窗、主窗口、托盘）→ 应用服务（记录、周报、提醒、AI、导入导出）→ 数据访问层（MySQL）及外部 AI 服务适配器。提醒调度和业务逻辑独立于界面，可单独测试。

**技术依据：**[.NET 支持策略](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)、[Windows 应用通知](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-dotnet)、[MySqlConnector](https://mysqlconnector.net/)、[DbUp MySQL 包](https://www.nuget.org/packages/dbup-mysql)、[DeepSeek API 文档](https://api-docs.deepseek.com/)、[ClosedXML](https://github.com/ClosedXML/ClosedXML)。

## 4. 功能拆解

### 4.1 桌面交互

**已确认的界面风格：**采用 Windows Fluent 风格，整体简洁、轻量、圆角化；浅色和深色主题跟随 Windows，强调色跟随系统强调色。

**视觉与布局规范：**

- 使用低装饰卡片、适度留白和清晰的标题层级；优先使用系统字体、图标与原生交互习惯，避免过度动画和大面积半透明影响阅读。
- 浅色、深色界面分别提供匹配的背景、表面、文字、边框及状态色；系统主题或强调色变化时同步更新。强调色用于主要按钮、选中态和焦点提示，保证文字可读。
- 悬浮窗以小巧、不遮挡工作为目标，显示当前周、添加记录、打开周报和最近一次提醒状态；收起后仍可通过托盘恢复。具体尺寸和组件间距在界面原型中确定。
- 主窗口以清晰导航组织工作记录、周报、历史和设置；周报编辑突出正文及保存操作，DeepSeek 生成入口与用户确认预览保持清晰区分。
- 工作记录、历史、导入导出和设置界面共用按钮、输入框、卡片、弹窗及状态反馈样式；空状态、加载、保存成功和错误均提供明确文本，不仅依赖颜色表达。
- 支持键盘导航、可见焦点、系统缩放与高对比度；在系统视觉效果不可用时使用可读的纯色背景，不影响操作。

- 悬浮窗展示当前周、添加记录、打开周报和最近一次提醒状态；支持拖动、置顶、收起和位置持久化。
- 托盘菜单至少包含打开主窗口、显示或隐藏悬浮窗、设置、退出；关闭窗口时的行为在设置和界面中明确。
- 考虑多显示器、分辨率变化和屏幕边界：位置失效时将窗口移回可见区域。
- 系统通知不可用或被禁用时，通过应用界面明确提示；通知不依赖悬浮窗处于展开状态。

### 4.2 工作记录与周报

- 工作记录包含日期、内容、创建时间和更新时间，支持新增、修改、删除和按周查询。
- 生成草稿时按所选周汇总工作记录，用户可编辑本周工作、下周计划及问题与风险。
- 显式保存成功后才提示成功；记录或周报未保存时提醒用户，失败时保留界面输入并允许重试。
- 历史列表按周倒序展示，支持打开和修改；删除需二次确认。
- 本地 MySQL 是首版历史数据的持久化来源。数据库不可用时明确显示错误，不将未持久化内容标记为已保存；应用退出或崩溃后的未保存内容不保证恢复，除非后续增加可靠的本地草稿机制。

### 4.3 AI 辅助生成

- 接口固定使用 `https://api.deepseek.com/chat/completions`，通过 HTTPS 和 `Authorization: Bearer <API Key>` 认证；首版使用非流式对话请求，默认模型为 `deepseek-flash`，模型名称可配置。具体请求字段和模型可用性以 [DeepSeek 官方文档](https://api-docs.deepseek.com/)为准。
- 设置页面支持配置模型和 API Key，以及检查连接、修改或删除配置；密钥输入时遮蔽显示，仅保存在当前 Windows 用户可访问的受保护存储中。用户自行从 [DeepSeek 平台](https://platform.deepseek.com/api_keys)获取 API Key；连接检查如需实际调用，应事先提示可能产生费用。
- 用户选择本周工作记录并主动点击生成或润色，确认发送内容及服务目标后调用 AI；展示加载、取消与结果状态。应用不会在提醒时自动上传数据。
- 将 AI 结果作为可编辑草稿展示，用户确认应用后才替换当前编辑内容，仍需显式保存至 MySQL；已有未保存编辑不可被静默覆盖。提示用户核对事实，AI 不得被视为事实来源。
- 接口密钥错误、额度不足、限流、网络超时、服务异常、响应不符合预期时显示明确原因或可操作提示；保留原内容，允许用户手动重试或继续手动编辑，避免不必要的自动重复付费请求。
- 使用 HTTPS 连接远程服务，避免在日志、错误信息、导出文件或源码中记录 API Key、请求正文和 AI 返回正文；提示服务商的数据处理政策及可能产生的费用。

### 4.4 导入导出

- JSON 备份包含格式版本、导出时间、工作记录和周报正文及其必要日期字段，不包含 MySQL 凭据、API Key、AI 配置或提醒去重状态。赋予工作记录稳定的跨导入标识，周报按周起始日期识别，支持重复导入时检测冲突。
- Excel 使用 `.xlsx` 格式，同样支持完整业务数据往返：包含“格式信息”“工作记录”“周报”三个工作表，分别保存格式版本与导出时间、工作记录及周报字段；工作记录包含稳定业务标识，周报按周起始日期识别。字段、日期和时间格式在模板文档中明确，与 JSON 的数据语义一致。
- 提供 Excel 导入模板；首版导入应用导出或符合模板的 `.xlsx` 文件，不默认支持任意表格、旧版 `.xls` 或含宏工作簿。校验工作表、列名和单元格类型，指出错误所在工作表及行列；不执行公式、宏或外部链接，业务数据单元格中的公式视为无效输入。
- Excel 导出将业务文本按文本单元格写入，避免以 `=`、`+`、`-`、`@` 等开头的内容被当作公式；导出前检查单元格和工作表的格式限制，超限时明确报错，不截断数据或生成不完整备份。JSON 可作为超出 Excel 限制时的备份方式。
- 导出完整数据到用户选定的本地文件；导出前说明文件含明文业务数据，仅在写入成功后提示成功。支持单篇周报导出 Markdown，明确 Markdown 不用于恢复。
- JSON 和 Excel 导入前均校验文件版本、结构、必填字段、日期、周周期及文件内部重复项，展示记录数量、冲突数量和导入方案；无法识别的版本或无效文件须拒绝并说明原因。
- 用户确认后在数据库事务中执行导入：默认跳过已存在记录；选择覆盖时按稳定标识或周起始日期替换对应业务数据；取消不修改数据库。任一步失败则回滚整次导入并报告错误，完成后展示新增、覆盖、跳过数量。
- 不在导入时修改现有数据库连接、密钥或提醒状态。覆盖前提示不可撤销并建议先导出备份；导入使用数据而非执行文件内容。

### 4.5 定时提醒

- 在应用启动和系统时间、时区变化及系统恢复运行时重新计算下一次提醒；使用系统当前本地时间，而非固定 UTC 偏移。
- 按“周 + 提醒类型（周四/周五）”记录提醒状态，保证同一计划时间点最多触发一次；两次提醒分别独立。
- 为避免依赖 MySQL 可用性而漏提醒，提醒去重状态保存在受当前用户保护的本地应用数据中；读取或写入失败时明确提示，并记录诊断信息。历史业务数据仍存 MySQL。
- 提醒内容包含对应周和操作入口；点击后打开该周周报，尚未生成时打开生成草稿入口。
- 多实例通过单实例机制避免重复调度；时间跳变、重复唤醒、跨周和重启均需覆盖测试。
- 记录调度、触发和失败等必要日志，不记录密码及周报正文。

### 4.6 数据模型初稿

通过迁移创建独立应用数据库和表；具体字段类型、索引、外键及字符集在实施时确定。

| 表 | 核心字段 | 约束与用途 |
| --- | --- | --- |
| `work_entries` | 主键、稳定业务标识、工作日期、内容、创建/更新时间 | 稳定业务标识唯一，工作日期建立索引，支持跨库导入去重及按周查询 |
| `weekly_reports` | 主键、周起始日期、周结束日期、本周工作、下周计划、问题与风险、创建/更新时间 | 周起始日期唯一，保证一周一份；日期遵循约定的周周期 |
| DbUp 迁移日志表 | 脚本标识、应用时间等 | 由 DbUp 管理，用于记录已执行脚本；实际表名随配置确定 |

周报正文是保存时的独立快照；后续修改工作记录不会静默覆盖已保存周报。是否提供显式重新汇总及冲突处理，随模板需求确认。

## 5. 分阶段开发任务

| 阶段 | 任务 | 交付与验收 |
| --- | --- | --- |
| 0. 需求确认与技术验证 | 确认第 2 节规则；验证第 3 节技术栈的托盘、通知注册和激活、唤醒、MySQL 迁移及 DeepSeek 接口 | 完成最小可运行验证，确认兼容的依赖版本及安装流程 |
| 1. 项目基础 | 建立解决方案、分层结构、配置与日志；加入单实例控制、测试项目和迁移机制 | 应用可启动退出；基础测试和构建通过；敏感配置不入库 |
| 2. 桌面常驻 | 建立 Fluent 风格主题与通用控件，绘制主要界面原型；实现悬浮窗、拖动置顶、托盘菜单、窗口恢复、位置持久化和可选自启动 | 浅色、深色和系统强调色正确呈现；正常关闭、恢复、退出及多显示器场景可验证 |
| 3. 数据基础 | 实现连接配置与检查、凭据安全保存、数据库迁移、工作记录增删改查 | 本地 MySQL 可初始化；重启后记录保留；断连和认证失败有明确反馈 |
| 4. 周报与历史 | 实现按周查询、草稿生成、编辑保存、历史列表及删除确认 | 同一周不重复创建；既有编辑不被重复生成覆盖；历史数据重启后可查询 |
| 5. 提醒 | 实现本地时间调度、通知点击、去重、恢复补发及失败提示 | 两个时间点独立触发；托盘运行可提醒；时间变化、重启和唤醒符合确认规则 |
| 6. AI 接入 | 实现 DeepSeek 模型与密钥配置、密钥保护、发送确认、接口调用、草稿预览及异常处理 | 使用 DeepSeek 完成生成和编辑；失败不覆盖原内容；密钥不泄漏到日志或导出 |
| 7. 导入导出 | 定义版本化格式，实现 JSON 与 Excel 备份恢复、Excel 模板、冲突预览与事务导入、Markdown 导出 | 两种格式均完成跨数据库往返及重复导入测试；Excel 校验、冲突和失败处理符合规则 |
| 8. 发布与验收 | 完成端到端测试、安装/卸载与升级验证，编写使用、AI 配置、导入导出和故障排查文档 | 在干净 Windows 环境按文档部署并完成一次完整周报及数据恢复流程 |

阶段 1 后，桌面常驻和数据基础可并行；周报依赖数据基础，提醒依赖桌面常驻及周报入口，AI 接入依赖周报编辑入口，导入导出依赖数据模型和周报功能；最终验收依赖上述功能完成。工期需在需求、团队投入和技术验证结果明确后估算，避免提前承诺日期。

## 6. 验证与验收清单

1. **提醒时间：**使用可注入时钟验证周四 17:00、周五 10:00 分别触发；接近边界、不同时区、系统时间调整、跨周均正确。
2. **提醒可靠性：**验证托盘运行、重启、休眠恢复和多实例；在约定补发窗口内外分别检查结果，同一计划时间点不重复；数据库断连时提醒仍可触发。
3. **周报一致性：**同一周重复生成不会覆盖已有内容；工作记录修改不会静默改变已保存周报；周起止边界数据归属正确。
4. **持久化：**新增、修改和删除后重启应用，直接从本机 MySQL 验证历史数据及周唯一约束；迁移在新库和已有库升级场景均可执行。
5. **异常路径：**模拟 MySQL 未启动、密码错误、断连、通知权限关闭及本地提醒状态不可写；显示明确错误，不误报保存或提醒成功。
6. **桌面体验：**检查悬浮窗遮挡、拖动、隐藏恢复、窗口关闭与退出、多显示器和自启动设置。
7. **部署：**在干净 Windows 环境按文档配置 MySQL、连接并运行；安装、升级和卸载流程明确说明哪些数据会保留。
8. **AI：**使用模拟服务覆盖成功、认证失败、余额不足、限流、超时、取消和无效响应；验证 DeepSeek 请求地址、认证和响应解析，以及发送前确认、原内容保护、显式保存、密钥和正文不进入日志或导出文件。使用用户授权的 API Key 和非敏感测试数据进行一次真实 DeepSeek 接口验证。
9. **导入导出：**分别将包含多周记录和周报的数据导出到 JSON、Excel 并导入空数据库，逐字段核对；两种格式均验证重复导入的跳过和覆盖、无效文件、版本不支持及中途失败时无部分写入。Excel 额外验证模板、缺列、错误单元格、公式、超限文本及以公式符号开头的文本；检查 Markdown 输出和备份不含凭据。
10. **界面风格：**在 Windows 浅色、深色和高对比度模式下检查悬浮窗及主要页面；切换系统主题与强调色后确认界面同步更新。检查键盘焦点、常见系统缩放比例及空状态、加载和错误提示的可读性。

优先使用单元测试覆盖周计算、调度、去重、草稿及导入规则，并以模拟服务测试 AI 异常；使用真实 MySQL 的集成测试覆盖迁移、数据操作和导入事务；使用人工端到端测试验证 Windows 通知、托盘、休眠与安装行为。测试数据不得使用真实敏感内容。

## 7. 风险与后续决策

- **常驻与系统通知限制：**系统省电、通知权限和进程退出会影响提醒；通过清晰设置、状态提示和已确认的补发规则降低影响。
- **MySQL 运维成本：**本地数据库需要安装、启动和备份；提供连接诊断与操作文档。是否提供一键安装或改用嵌入式数据库需另行决策，首版仍按 MySQL 设计。
- **数据安全：**数据库账号权限应尽可能收敛；如现有本地账号权限过高，建议用户自行创建专用最小权限账号。不要把密码或周报正文写入日志。
- **AI 隐私与费用：**DeepSeek 会接收用户确认发送的内容，具体留存政策、可用性和收费以 DeepSeek 官方说明为准；未配置或服务不可用时仍可手动编写周报。
- **备份与恢复：**JSON 和 Excel 导出文件包含明文业务数据，需由用户妥善保管；应用内手动导入导出不替代数据库级完整备份，文档需说明 MySQL 备份恢复操作。自动备份属于待确认范围。
- **后续扩展：**可在需求确认后考虑模板配置、更多文件格式、自动启动任务和跨设备同步。
