## 1. 目标与已确认范围

在现有 Windows 桌面周报工具上增加两项能力：

1. **本地容灾：**本机 MySQL 不可用时，仍可将全部业务数据保存到本地 SQLite；MySQL 恢复后自动同步可安全合并的变更，有冲突时由用户处理。
2. **智能机器人：**悬浮精灵根据当前有效业务数据和存储状态，给出有依据、可操作的建议，不以固定闲聊冒充状态感知。

本计划基于以下已确认选择：

- 数据库范围仍为**现有本机 MySQL**，不扩展远程连接。本项目当前的 `DatabaseConnectionSettings` 明确只接受本机地址；用户所说的“远程数据库不可用”在本计划中按“现有 MySQL 不可用”处理。
- 同步采取**自动同步无冲突变更，有冲突时提示用户**；不能安全判断时按冲突或待处理项处理，不猜测覆盖。
- 离线范围覆盖工作记录、Git 项目和本机绑定、Git 工作项与提交去重信息、工时、周报，以及现有导入导出操作。Git 仍需本机 Git 和可访问的仓库。
- 本次交付是开发计划；具体实现、数据库迁移和数据同步均不在编写计划时执行。

## 3. 产品行为

### 3.1 本地优先与存储状态

为避免“请求已在 MySQL 提交、但连接中断导致重复写入”及切库时丢失修改，建议启用容灾后统一采用**本地写入优先**：

1. 业务读取以 SQLite 当前有效视图为准；用户保存时，在同一 SQLite 事务中提交业务变更和待同步记录。SQLite 提交成功才提示“已保存到本机”。
2. MySQL 可用时后台尽快同步；在 MySQL 事务确认成功且本地同步状态已持久化之后，才显示该变更已同步。界面不得把“保存到本机”说成“已保存到 MySQL”。
3. MySQL 不可用时继续使用本地数据，显示“本地模式 / 待同步数量 / 最近成功同步时间”；恢复后自动重试。显示的是最后成功镜像和本地修改，不保证包含断线期间其他客户端的变更。
4. 连接正常不代表所有内容已同步：状态至少区分**已同步、待同步、同步中、冲突待处理、连接或配置异常、本地存储异常**。如果同时存在多种状态，应同时展示关键原因和数量。
5. 现有数据库未配置、首次没有有效镜像、用户切换数据库、MySQL 身份变化或迁移未完成时，不伪装成正常同步；具体处理见第 4 节。
6. SQLite 文件损坏、不可写、空间不足或迁移失败时，保留文件、明确报错，不显示保存成功，不清空或自动新建替代数据。

启用容灾时，对现有用户提供说明及明确确认：本机 SQLite 将保存业务数据；首次建立镜像及必要的 MySQL 迁移会访问所选数据库。保持数据库密码、API Key 和提醒状态沿用现有独立受保护配置，不写入业务 SQLite 或同步队列。

### 3.2 无冲突自动同步

- MySQL 恢复后自动重试；只自动应用能证明基线未改变、目标标识和关联约束均匹配的操作。
- 本地和 MySQL 同时新增相同自然键、编辑同一条记录、删除与编辑竞争、关联对象变化或基线缺失时，保留双方数据并显示冲突；不按时间戳或“最后写入者获胜”静默覆盖。
- 同一事务形成的关联变更作为原子同步组；存在依赖的后续变更在前置组完成或解决冲突后再执行。无依赖的安全变更可继续同步。
- 对冲突提供本地版本、MySQL 版本和必要的基线信息；允许用户选择保留一方或编辑合并结果，再次检查目标版本并确认。用户未处理时不删除任何一方。
- 同步与现有“从本地 Git 仓库导入提交”是两个不同操作：前者同步数据库业务变更，后者仍需预览及用户确认。

### 3.3 机器人互动

保留现有单击、双击、拖动、问候、提醒与庆祝行为，新增右键入口“查看本周进展”。机器人使用与主界面一致的 SQLite 有效视图及同步状态：

| 条件 | 建议文案示例 | 操作入口 |
| --- | --- | --- |
| 有记录、周报未保存 | “本周已有工作记录，周报还没保存，要整理一下吗？” | 打开或生成本周周报 |
| 已保存周报 | “本周周报已保存，可以打开检查是否需要补充。” | 打开本周周报 |
| 存在无法得到工时的工作项 | “本周有 2 项工作还没有可用工时，可以检查一下。” | 打开相关工作项页面 |
| 本周没有记录 | “本周暂时没有工作记录，需要记一笔吗？” | 打开工作记录 |
| 本地有待同步变更 | “内容已保存在本机，还有 3 项变更等待同步。” | 查看同步状态 |
| 存在同步冲突 | “有数据需要你确认，现有内容已保留在本机。” | 查看冲突 |
| 本地数据无法读取 | “暂时无法读取本周状态，请检查本地存储。” | 打开存储状态或设置 |

- “没有记录”只表示查询结果为空，不推断用户没有工作；“已保存”不代表编辑器不存在未保存修改。工时数按 `WeeklyReportDraftBuilder` 的现有口径计算，不把估算值当作已确认值。
- 优先展示需要处理的存储异常和冲突，再展示业务建议；提供状态来源和最近同步时间，离线时不声称 MySQL 也已更新。
- 在现有空闲调度上增加低频主动建议：机器人可见、至少 5 分钟无交互、没有更高优先级气泡时才考虑显示；建议每天最多一次，跨重启记住日期。温和和活泼档默认开启，安静档默认关闭，另提供独立开关。
- 主动建议尊重夜间免打扰和临时静音；用户主动点击查看不受夜间限制。正式提醒仍按既有时间和系统通知规则执行，不额外补发。
- 主动建议与现有闲聊互斥：同一轮空闲调度最多展示一条，避免增加消息密度；数据获取异步进行，禁止在 UI 线程阻塞。
- 按钮只导航到相应页面，不自动写入、删除、生成 AI 结果或覆盖编辑器。跳转复用现有未保存修改确认和忙碌状态保护。
- 默认信息卡片样式也必须能看到存储状态并进入状态详情；智能文案和动画仅在精灵样式中提供，不强制切换样式。

## 4. 数据一致性与恢复设计

### 4.1 身份、初始化与镜像

1. SQLite 在当前用户的 `%LOCALAPPDATA%\WeeklyReport` 下使用独立业务数据库；数据库文件和同步队列均含明文业务数据。本计划不宣称它们已加密，沿用当前用户权限边界，并在文档中说明备份和设备保护责任。
2. 分别维护 SQLite 结构版本和 MySQL 同步协议版本。首次启用时先检查连接、版本、权限和目标数据库，再经用户确认执行版本化迁移；MySQL DDL 可能隐式提交，不能承诺整个迁移回滚。
3. 为已确认的 MySQL 数据库记录持久身份，SQLite 记录绑定身份及连接配置标识。连接配置变化、数据库被替换或恢复、身份不匹配、协议不兼容时，暂停同步并要求用户检查；不得将待同步数据送到未经确认的数据库。数据库克隆可能保留相同身份，因此恢复或复制操作也需显式核对。
4. 首次在线初始化从 MySQL 获取**一致性快照**，包括项目绑定、全部工作项、提交链接、周报、删除状态和并发基线；写入 SQLite 临时初始化事务，校验完成后才标记镜像可用。不得使用缺少绑定和修订信息的现有 `BackupDocument` 替代完整镜像。
5. 首次启动即不可连接或无法完成一致性快照时，明确提示“尚无可用镜像”。允许用户选择建立空的本地工作区以继续录入，但将其标记为**无已验证基线**：恢复后先核对目标身份和数据，无法证明安全的合并进入冲突处理；不把空库解释成 MySQL 数据为空，也不静默覆盖。
6. 不自动用新快照覆盖未同步修改。重新绑定或重建镜像前展示待同步和冲突数量，并提供导出；取消或失败时保留原本地文件及队列。

### 4.2 本地事务与同步记录

- 为每个用户确认的业务事务创建稳定的操作组 ID、关联对象键、原始基线、变更内容和依赖关系；业务表更新、删除记录和队列入队必须同一 SQLite 事务提交。
- 手工记录、周报的物理删除也必须保留可同步的删除意图及基线；Git 工作项沿用软删除及提交去重语义。禁止重放时静默恢复已删除工作项。
- 一个 Git 同步确认或一次备份导入可能修改多表、多行，必须记录为一致的事务组，保留现有预览、用户确认、原子提交和失败回滚语义。
- 本地连续编辑同一对象时保留正确的先后依赖与基线；不得因为压缩队列而丢失删除、已确认工时或中间引用。
- 读取和写入在完整切换前不得绕过统一入口。盘点工作记录、项目配置、Git 导入和重算、周报、备份导入导出、状态查询等所有读写；不能只给部分仓储增加 SQLite。
- 业务操作与后台同步并发时，使用清晰的本地事务边界和单一同步协调器；保持原有编辑器版本检查，后台刷新不得覆盖未保存编辑。

### 4.3 比较、提交和重试

1. 自动同步前核对数据库身份、协议版本及操作组依赖，读取目标行和自然键并与基线比较；对缺失基线、对象归属或约束不一致的情况标记冲突。
2. MySQL 使用 InnoDB 事务，将基线比较、必要的行/键范围锁或等价并发控制、业务写入和**操作组去重记录**放在同一事务。对不存在的自然键也要依赖唯一约束及事务内冲突处理，不能只在事务外先查再写。
3. 同一操作组 ID 重试时，MySQL 去重记录必须能确认它对应同一内容：已提交则返回已应用结果；ID 与内容不匹配则停止并报错。业务事务失败时去重记录不能单独提交。
4. 如果提交响应丢失，保留“结果待确认”，重新连接后使用同一操作组 ID 查询或重试；不得生成新 ID 盲目重复操作，也不得提前标记成功。
5. MySQL 确认后，在 SQLite 事务中持久化确认结果、更新相关基线并推进队列。程序在任意步骤崩溃重启后都应可安全恢复；SQLite 状态未落盘时可凭同一 ID 识别 MySQL 已提交。
6. 周期性读取 MySQL 的一致性变化，并与本地基线和待同步数据进行三方比较；仅更新无本地待处理变更的对象，双方改变则记录冲突。无法证明删除或变更范围时不得将缺失行直接视为安全删除。
7. 冲突解决再次比较当前 MySQL 状态；预览后目标发生变化时要求重新预览。关联事务组中的冲突不能拆成破坏外键、项目/日期唯一性或提交去重约束的半成功状态。
8. 同步探测提供有上限的退避重试，并在启动、唤醒和用户点击“立即同步”时重新评估；认证失败、权限不足、迁移错误、数据校验失败等显示明确原因，不能无限重试或当成普通断线。

### 4.4 备份和恢复边界

- SQLite 是工作副本及容灾数据源，不等于独立备份：磁盘损坏、误删、勒索软件或文件损坏仍可能造成丢失。继续提供现有 JSON/Excel 导出，并建议用户将备份放在独立位置。
- 使用 SQLite 在线备份 API 或等价一致性机制生成完整本机备份，包含业务表、同步基线、队列及状态；WAL 模式下禁止只复制正在使用的主数据库文件并宣称其完整。
- 区分“完整本机恢复”和“JSON/Excel 业务导入”：前者包含本机绑定及待同步状态，后者保持现有不导出路径、作者配置、密钥和提醒状态的约定；备份文件可能包含敏感工作内容。
- 恢复完整本机备份前必须预览备份时间、数据库身份、待同步和冲突数量，并确认；恢复后先暂停自动同步、校验目标身份和基线，不能直接把旧队列重放到其他或已回滚的数据库。
- 卸载、升级和失败处理不自动删除 SQLite 文件、待同步队列或用户导出的备份。

## 6. 分阶段任务与验收

### 阶段 1：规格冻结与兼容性验证

- [ ] 梳理所有业务读取、写入、删除、事务和导入导出入口，建立覆盖清单；确认哪些界面具备未保存编辑及并发保护。
- [ ] 明确 SQLite 模式、驱动、线程与迁移策略；验证日期、UTC 精度、字符串长度、排序规则、外键、唯一键和工时数值与现有业务语义一致。
- [ ] 设计数据库身份、版本、操作组和冲突数据格式，记录旧版本客户端、外部修改、备份恢复和数据库替换的兼容边界。
- [ ] 在隔离环境验证 MySQL 一致性快照、并发比较及提交结果不确定时的幂等协议；无法证明安全时暂停后续自动同步实现。

**验收：**形成接口与数据流设计、入口清单和故障状态表；明确初始化或迁移需用户确认，未配置 MySQL 时无误报。

### 阶段 2：SQLite 完整业务能力

- [ ] 建立 SQLite 初始化、版本化迁移及仓储契约测试，支持现有全部业务读取和事务写入。
- [ ] 保持项目本机绑定、Git 提交去重和删除标记、工时估算及确认、周报周唯一和编辑保护。
- [ ] 支持首次镜像、无基线本地工作区、本地存储错误提示，以及同一事务中的业务变更和待同步记录。
- [ ] 让 JSON/Excel/Markdown 导出与 JSON/Excel 导入使用当前有效数据；完整本机备份采用一致性备份机制。

**验收：**隔离测试中停止 MySQL 后，完整工作流仍能保存、重启后读取、预览并确认 Git 同步和备份导入；SQLite 不可写时不能显示成功。现有导入冲突处理和文件格式约定不变。

### 阶段 3：自动同步、冲突与恢复

- [ ] 依赖阶段 2 的事务化操作组，实施身份检查、MySQL 去重记录、事务内基线比较、依赖排序和安全重试。
- [ ] 增加 MySQL 到本地的安全刷新及三方比较；设计并实现冲突列表、版本对比、用户确认和再次校验。
- [ ] 为后台同步实现生命周期、退避、取消和状态通知；提供立即同步、待处理数量和最近成功时间。
- [ ] 在恢复、配置变更、迁移失败和身份不一致时安全暂停，提供可理解的恢复入口。

**验收：**无冲突变更在 MySQL 恢复后自动同步；冲突和依赖项不被覆盖，独立安全变更可继续。反复重试及重启不会重复提交、丢失删除或误报已同步。

### 阶段 4：智能机器人与存储状态

- [ ] 在阶段 2 的统一有效数据源和阶段 3 的同步状态之上实现上下文查询与纯策略；保留当前保存状态缓存的失效机制，业务变更、同步或切换后更新显示。
- [ ] 实现“查看本周进展”、低频主动建议、设置项、卡片状态入口和冲突入口；保留现有机器人交互与正式提醒。
- [ ] 对数据库读取失败、镜像尚未建立、过期镜像、待同步和冲突分别显示可区分的状态；仅提供导航，不执行写入。

**验收：**表格中每一类场景都能通过测试产生对应提示与正确入口；夜间、静音、每天一次、跨重启、气泡优先级和未保存编辑保护均符合第 3.3 节。

### 阶段 5：端到端验收与发布

- [ ] 更新 [README](../README.md) 和直接相关的设置、备份恢复说明，明确本地优先、自动同步、冲突、隐私和 MySQL 单机范围。
- [ ] 运行相关单元、桌面和隔离数据库集成测试，再执行解决方案构建、发布及安装升级验证；记录无法完成的真实环境验证。

**验收：**构建和相关测试通过；发布包在目标 Windows 环境可以加载 SQLite 原生组件；升级、卸载和重装后用户数据仍按文档保留。真实 MySQL、异常断连和 Windows 安装验证未执行时明确标注未验证。

## 7. 必测场景

| 场景 | 必须满足 |
| --- | --- |
| 首次启用、MySQL 正常 | 镜像完整且一致，包含 Git 本机绑定、提交去重和删除状态；完成后才能标记已初始化。 |
| 首次启动 MySQL 不可用 | 提示没有有效镜像；空工作区须用户选择，恢复后缺基线内容不得静默覆盖。 |
| 停止 MySQL 后新增、修改、删除 | 保存到 SQLite 并留下待同步意图；重启后数据和状态仍在。 |
| MySQL 事务提交前中断 | 本地修改保留；恢复后同一操作组安全重试。 |
| MySQL 已提交但响应丢失 | 重试相同操作组 ID，识别已应用，不重复创建；本地最终确认。 |
| MySQL 提交后、本地确认前崩溃 | 重启后识别已提交操作并修复本地状态，不误报失败或重复应用。 |
| 本地和 MySQL 修改同一记录 | 两个版本都保留并标记冲突；预览后 MySQL 再改变则要求重新预览。 |
| 双方新增同周周报或同项目同日 Git 项 | 按自然键冲突处理，不生成违反唯一约束或错误关联的数据。 |
| 一方删除、一方修改 | 删除意图与修改均保留并要求处理；Git 已删除项不会被静默重建。 |
| Git 多行事务中途失败 | 项目、工作项、提交链接和工时不出现部分提交；重试不重复导入。 |
| 认证失败、权限不足、协议不匹配 | 本地数据保留并显示具体异常；不把故障当同步成功。 |
| 数据库切换、替换或备份恢复 | 暂停同步并核对身份和基线；不得向错误目标重放队列。 |
| SQLite 满盘、损坏、不可写 | 不显示保存成功，不清空现有文件；提供错误与恢复提示。 |
| SQLite 在线备份及恢复 | 恢复后业务数据、绑定、基线和队列一致；恢复后先暂停并校验目标。 |
| 状态、提醒与机器人 | 离线文案注明本机状态；未知不等于未保存；正式提醒不变，冲突和高优先级提醒不被闲聊覆盖。 |
| 导入、导出及未保存编辑 | 保持预览确认和失败回滚；后台刷新、机器人跳转和冲突处理不静默覆盖编辑器。 |

## 8. 不纳入第一版

- 不支持远程 MySQL、多设备自动发现或多人协同；即使出现其他客户端修改，也必须检测冲突而非假定不存在。
- 不做通用聊天、语音交互、持续监听或自动发送业务内容给 AI。
- 不自动安装 MySQL，不静默升级用户数据库，不在没有有效确认的情况下覆盖生产数据。
- 不承诺本地 SQLite 替代异地备份；暂不承诺数据库文件加密或所有机器故障下的数据零丢失。
