# 备份功能离线化改造计划

## 1. 背景与依据

依据[离线可用与本地优先存储计划](./离线可用与本地优先存储计划.md)（执行计划）与[本地容灾与智能机器人扩展开发计划](./本地容灾与智能机器人扩展开发计划.md)（历史参考）对数据备份的要求，对现有备份功能做差距改造。本计划是存储计划 **Phase 1 的组成部分**（导入导出切有效视图）并补充其 Phase 1/3 中"完整本机备份"的新增能力，不改变 Phase 0 的 Go/No-Go 结论与 ADR 决策权。

三项不变性原则（源自两份文档，本计划全程遵守）：

1. **SQLite 不是备份**：同机同盘不构成容灾；数据保护仍靠用户独立位置备份 + MySQL 自身备份。README 与设置页统一使用"离线可用与本地优先存储"措辞。
2. **现有 JSON/Excel/Markdown 导入导出用户语义不变**：文件格式、版本校验、冲突预览/跳过/覆盖、事务原子性、失败回滚全部保持。
3. **`BackupDocument` 不得升级为镜像格式**：它保持纯业务交换模型；完整本机备份是独立的新格式。

## 2. 现状与差距

| 现状 | 文档要求 | 差距 |
| --- | --- | --- |
| `IBackupStore`（Capture/Import）仅 MySQL 实现（[SqlSugarBackupStore](../src/WeeklyReport.Infrastructure/Persistence/SqlSugarBackupStore.cs)），SERIALIZABLE 事务 + FOR UPDATE + 基线比较 | 业务读写统一走"当前有效视图"；MySQL 停止后导入导出完整可用（Phase 1 验收） | 缺 SQLite 侧实现与按存储模式的 DI 路由 |
| 导入直写 MySQL 事务 | 本地优先模式下导入写入 SQLite 且**同一事务入队** `sync_operation`；原子回滚语义在 SQLite 事务上等价成立 | 导入入队未实现 |
| 仅 JSON/Excel（+单篇 Markdown）业务交换 | 新增**完整本机备份**：SQLite 在线备份 API 单文件，含业务表 + 基线 + 队列 + 状态；恢复前预览、恢复后暂停同步并校验身份 | 新能力整体缺失 |
| 危险操作（重建镜像/禁用本地优先/回退）尚不存在 | 这些操作出现时必须先展示待同步/冲突数量并允许导出（逃生口） | 条件性联动，随 Phase 2/3 功能落地 |
| README 已有"备份、导入和恢复"章节 | 措辞改为"离线可用与本地优先存储"；补充完整本机备份说明与明文数据提示 | 文档更新 |

## 3. 设计决策

### 3.1 双实现与路由（不改 `BackupService`）

- `BackupService`/`BackupFileService`/`BackupViewModel` 面向 `IBackupStore` 接口，保持不动。
- 新增 `SqliteBackupStore : IBackupStore`（Infrastructure/Persistence），与 `SqlSugarBackupStore` **共享同一组契约测试**（从现有 MySQL 行为提取，见切片 1）。
- DI 注册（App.xaml.cs）：按当前存储模式解析 `IBackupStore`——MySQL-only 时注入现有实现；本地优先时注入 SQLite 实现。路由器为仅一处的新增代码，不引入第三种间接层。

### 3.2 导入入队语义（依赖 Phase 1 的操作组机制）

- SQLite 实现的 `ImportAsync` 在**同一个 SQLite 事务**内：基线比较 → 规划（复用 `BackupImportPlanner`）→ 业务写入 → `sync_operation` 入队（一次导入 = 一个操作组，含依赖顺序）→ 提交。
- 现有"预览后数据库已变需重新预览"的保护在 SQLite 上等价实现（比较基线快照）。
- 冲突策略（跳过/覆盖）语义不变；覆盖同样以删除意图 + 变更形式入队，不物理绕过队列。

### 3.3 完整本机备份格式（新增）

- **格式**：单个 SQLite 数据库文件，扩展名 `.wrbak`，由 SQLite 在线备份 API（驱动 ADR-02 定稿后确认 API 形态，如 `BackupDatabase`）从当前工作副本一致性生成；内容 = 业务镜像表 + `local_meta` + `sync_operation` + `sync_conflict` 全量。
- **禁止**在 WAL 模式下直接复制使用中的主库文件冒充备份（切片 4 的契约测试固化此点）。
- **生成入口**：设置页存储区块"备份本机数据"→ 保存文件对话框 → 生成后显示时间与待同步/冲突数量。
- **恢复流程**：选择 `.wrbak` → 以只读方式读取 `local_meta` 与队列统计，弹出**恢复预览**（备份时间、数据库身份、待同步数、冲突数、与当前副本的身份匹配结果）→ 用户确认 → 停止同步协调器 → 原子替换本地文件 → 重启后保持"同步暂停"状态并校验身份/基线 → 用户显式恢复同步。
- **身份不匹配**（备份属于其他数据库）时默认拒绝恢复，仅允许用户明确确认"恢复到当前绑定"的高级操作。
- 与 JSON/Excel 导入在 UI 与文案上明确区分为两种能力：完整本机恢复（含绑定与队列，敏感）/ 业务数据导入（不含路径、作者配置、密钥、提醒状态）。

### 3.4 措辞与逃生口

- README"备份、导入和恢复"章节与设置页：全部改为"离线可用与本地优先存储"口径；新增完整本机备份小节；明文业务数据提示覆盖新格式。
- 条件任务（依赖 Phase 2/3 的功能入口出现时一并落地）：重建镜像、禁用本地优先、回退 MySQL-only、队列达上限——每处先展示待同步/冲突数量并提供"导出 JSON"逃生口；卸载/升级不删除 SQLite 文件、队列与用户导出的备份。

## 5. 测试与验收清单

| 场景 | 要求 |
| --- | --- |
| MySQL-only 模式备份（回归） | 现有 JSON/Excel/Markdown 行为与文件格式逐字节级不变；现有测试全绿 |
| 停止 MySQL 后导出 | JSON 全量 / Excel 多周 / Markdown 单篇均可用，内容来自 SQLite 有效视图 |
| 停止 MySQL 后导入 | 预览（数量/冲突）→ 确认 → SQLite 事务原子写入并入队；中途失败零部分写入 |
| 导入后恢复 MySQL | 操作组按依赖自动同步；重复导入同一文件去重语义与现有一致 |
| 完整本机备份一致性 | `.wrbak` 含业务表/基线/队列/状态；WAL 活动期间生成仍一致（对照直连校验） |
| 恢复预览与身份 | 展示时间/身份/待同步/冲突数量；身份不匹配默认拒绝；恢复后同步保持暂停直至用户确认 |
| 恢复后不重放错库 | 旧队列不会自动应用到身份不符或已回滚的数据库 |
| 措辞检查 | README/设置页无"容灾"字样；"本地保存"不表述为"MySQL 已保存" |
| 卸载/升级 | SQLite 文件、队列、用户导出备份不被自动删除 |

## 6. 风险与缓解

- **依赖 Phase 0 结论**：若 ADR-01 选 A2/A3，切片 3 的入队语义与切片 4 的备份内容随之简化（如 A3 仅入队不落镜像）；本计划切片 2–4 的实现细节以 ADR 为准，不提前锁死。
- **SQLite 在线备份 API 可用性**：列入切片 4 前置验证（ADR-02 驱动定稿后立即验证），不可用则改用 `VACUUM INTO` 等等价一致性机制并重测 WAL 场景。
- **契约测试提取偏差**：切片 1 从现有行为反推契约时若发现未定义行为（如空库导出），先以现网行为固化并记录，不在本计划内"顺手修正"。
- **双实现漂移**：契约测试强制双库同跑；禁止任何一侧绕过 `IBackupStore` 直连数据。

## 附录：备份链路入口清单（切片 0 盘点结果，2026-11-03）

### 读入口（导出侧）

| 入口 | 调用路径 | 说明 |
| --- | --- | --- |
| 全量捕获 | `BackupViewModel.ExportAsync` → `BackupService.CaptureAsync` → `IBackupStore.CaptureAsync` | JSON/Excel 导出的唯一数据源；明文导出确认对话框在 VM 层 |
| 周列表加载 | `BackupViewModel.LoadWeeksAsync` → `IWeeklyReportRepository.ListAsync` | Excel/Markdown 周选择的数据源，**独立于 CaptureAsync 的第二条读取路径** |
| Markdown 单篇 | `BackupFileService.ExportAsync(Markdown)` ← `BackupSelection.SelectWeeks` 后的 `Reports[0]` | 数据同样来自 CaptureAsync |
| 导入预览基线 | `BackupService.PrepareImportAsync` → `CaptureAsync` + `BackupImportPlanner.Prepare` | 基线快照即捕获结果 |

### 写入口（导入侧）

| 入口 | 调用路径 | 说明 |
| --- | --- | --- |
| 导入应用 | `BackupViewModel.ImportAsync` → `BackupService.ApplyImportAsync(userConfirmed)` → `IBackupStore.ImportAsync` | 唯一写入口，事务原子性由 store 实现保证 |
| 导入后刷新 | `BackupViewModel.RefreshAfterImportAsync` → 周列表重载（读） | 跨入口联动 |

### 现有保护机制（均有测试）

- `userConfirmed` 确认门禁（`BackupService`）+ 基线比较拒绝过期预览（store 层）
- 冲突策略选择（`IBackupReviewDialogs.ChooseImportPolicy`），取消不修改数据库
- `IsBusy` / `IsNavigationLocked` → `MainWindow.MainTabs.IsEnabled` 导航锁
- 中途失败整体回滚（MySQL 触发器注入验证）；文件层失败保留原文件并清理临时文件
- Markdown 仅供阅读、拒绝导入

### 切片 2 注意点（盘点结论）

- **周列表与全量捕获是两条读取路径**：接 SQLite 有效视图时必须同批接入，避免周选择列表与导出内容不一致。
- 触发器故障注入手法对 SQLite 可复用（支持等价触发器），契约钩子已按此设计。
