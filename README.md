# WeeklyReport

Windows 桌面周报工具：记录工作、汇总 Git 提交、生成与提醒周报。支持悬浮精灵、系统托盘、定时任务与数据导入导出；数据保存在本机 SQLite，无需安装数据库。

- 需求与阶段验收见[开发执行计划](./docs/开发执行计划.md)，架构决策见 [docs/adr](./docs/adr/)。
- **存储（SQLite-only 暂行决策，2026-11-09）：** 运行期间不连接 MySQL，业务数据全部保存在本机 SQLite 工作库（`%LOCALAPPDATA%\WeeklyReport\weekly-report.db`），不自动跨设备同步。从 MySQL 版本升级的迁移与回滚见《[SQLite 单机切换指南](./docs/SQLite单机切换指南.md)》。
- **验收状态：** 当前共 410 项自动化测试（单元 136、桌面 151、集成 123，其中 21 项需要真实 MySQL，覆盖保留但停用的同步代码）。单元和桌面测试通过；集成测试偶发失败，见[构建、发布和测试](#构建发布和测试)。备份往返、桌面主要业务、系统通知提交、升级安装与单实例运行已验证；真实 DeepSeek 请求、系统通知实际显示与点击、原生界面全流程人工回归（含 SQLite-only 改造后的设置页）及干净 Windows 环境的完整验收尚未完成。

## 功能特性

- **工作记录**：按日期记录内容与可选的已确认工时，本地事务保存。
- **Git 工作项**：读取本地仓库提交，按日期合并为工作项并估算工时；只读 `HEAD`，不克隆、不拉取、不推送。
- **周报**：周一至周日按周汇总，生成草稿、编辑、保存；支持 DeepSeek 润色。
- **提醒**：每周四 17:00 与周五 10:00 的 Windows 系统提醒；可选工作节律提醒（喝水休息）。
- **定时任务**：工作日自动同步当日 Git 提交、每周自动汇总周报草稿，时间可调。
- **悬浮窗**：信息卡片或代码绘制的矢量悬浮精灵（双击打开周报，挥手、跳舞、气泡提醒与本周进展建议）。
- **数据**：JSON / Excel / Markdown 导出，JSON / Excel 导入（冲突策略 + 事务回滚）；命令行完整工作库备份与恢复。

## 环境和安装

- Windows 10 版本 2004（内部版本 19041）或更新版本，x64。
- 无需安装数据库；首次启动自动创建空 SQLite 工作库。
- 使用 Git 工作项时，需要已安装 Git 并能从 `PATH` 调用 `git`。
- 构建源码需要 .NET 10 SDK；安装包自包含运行时，不要求另行安装 .NET。

安装包默认安装到当前用户的 `%LOCALAPPDATA%\Programs\WeeklyReport`，无需管理员权限。安装包目前未签名，可能被 Windows 应用控制或组织策略阻止；请通过正常签名、审批或受信任开发环境处理，不要关闭或绕过安全策略。

首次启动即可直接使用。若此前使用 MySQL 版本且尚未建立本地镜像，启动时会给出迁移指引——请按《[SQLite 单机切换指南](./docs/SQLite单机切换指南.md)》在旧版本完成迁移后再升级，或在确认后建立空白工作库。

## 日常使用

1. 在“工作记录”中填写日期、内容及可选的已确认工时。
2. 在“Git 工作项”中为每个本地仓库配置项目名、路径和作者匹配方式，选择日期范围，先预览再确认同步。
3. Git 提交按项目和本地日期合并为工作项。相邻提交间隔不超过 2 小时时才参与估算；跨项目重叠时段均分，自动估算每日最多 8 小时。估算是建议值，可手动修正并确认；无法推断不等同于零工时。
4. 在“周报”中选择日期，打开已有周报或生成草稿，编辑本周工作、下周计划和风险后保存。一周按周一至周日计算。
5. 关闭主窗口会隐藏到托盘；使用托盘菜单“退出”才会结束应用。Windows 登录时自启动默认关闭，可在“设置”中启用。
6. 悬浮窗支持两种样式，可在“设置”中切换并即时生效：默认**信息卡片**；**悬浮精灵**为代码绘制的矢量小精灵，双击打开周报，右键菜单支持打开周报、查看本周进展、挥挥手、跳个舞、打个招呼、安静 1 小时和收起；悬停查看本周与提醒状态，提醒触发时会跳动并弹出气泡。精灵可按本周记录和工时状态提供低频建议（仅导航，不会自动生成或保存周报），扩展动态动作与低频空闲舞蹈均可关闭；安静档默认不自动跳舞。信息卡片也可查看存储状态并进入本周进展。两种样式的位置都会保存并在重启后恢复。

删除 Git 工作项时会清除描述、工时、作者及提交摘要，但保留已处理提交的身份和时间，防止下次同步静默重建。需要调整已有项目或日期的自动估算时，可在 Git 工作项界面手动重算；已确认工时不会被覆盖。

## 提醒

应用运行或在托盘后台运行时，按系统本地时间在每周四 17:00 和周五 10:00 分别提醒，即使该周周报已保存也会提醒。启动、系统时间或时区变化及唤醒后重新计算；错过不超过 2 小时的提醒可补发，同一周的同一提醒不重复发送。

应用退出、关机或休眠期间不保证准点提醒。提醒去重状态保存在当前 Windows 用户受保护的本地配置中；通知禁用、状态不可写或发送状态不确定时，界面会提示。若已手动检查不确定的提醒，可在设置中确认该状态；确认不代表通知已送达，也不会自动重发。系统接收通知不代表用户一定看到横幅，仍受通知权限和勿扰模式影响。主窗口的“测试提醒”只发送测试通知，不占用定时提醒的去重状态；点击通知可打开对应周报。

设置中还可独立启用工作节律提醒：周一至周五工作时间（09:00–12:00、13:00–18:00）按 10:00、11:00、14:00、15:00、16:00、17:00 提醒喝水和休息。精灵可见时显示动画气泡，否则发送 Windows 通知；可选择“知道了”或“10 分钟后”。错过的提醒不会补发，稍后提醒落在工作时间外时会跳过；距离下一固定提醒不超过 5 分钟时会合并。该功能默认关闭，启用状态和稍后提醒时间保存在本地悬浮窗配置中。

“设置”中的“定时任务”默认关闭，开启后可在工作日 17:30 自动同步绑定 Git 仓库的当日提交，或在每周四 16:00 自动汇总并保存周报；时间可调整，周报任务也可调整星期，并支持手动立即执行。开启 Git 同步即授权自动写入工作项；删除冲突会跳过，浅克隆不会自动应用。已有周报不会被覆盖。任务结果显示在主窗口状态和悬浮精灵气泡中；应用关闭或休眠错过计划时间时不会补跑。AI 润色不会由定时任务自动发送。

## DeepSeek

在“设置”中填写模型和自己的 DeepSeek API Key；默认模型为 `deepseek-flash`。可先使用连接测试，该测试会发送固定的非敏感内容，并可能产生费用。生成总结前会展示准备发送的数据和目标地址，只有用户确认后才发送至 `https://api.deepseek.com`；返回内容也需再次确认才应用到编辑器，仍需手动保存周报。

请自行判断工作内容是否允许发送给外部服务。API Key 使用当前 Windows 用户的 DPAPI 保护，不包含在备份中；删除配置可移除本机保存的密钥。真实服务的模型、额度和价格以 [DeepSeek 官方文档](https://api-docs.deepseek.com/)为准。

## 备份、导入和恢复

业务交换（导入导出页）：

- JSON 导出全部业务数据；Excel 可选择一周或多周；Markdown 仅导出一份周报且不能导入。
- Excel 仅支持本应用导出或符合其模板的 `.xlsx`，不支持任意表格、`.xls`、宏、公式或外部链接。工作簿最多 64 MB，解压总量最多 256 MB，单个单元格最多 32,767 个字符；较大的业务数据可使用 JSON。
- 导入前会显示数量与冲突，默认可选择跳过；覆盖需再次确认，失败时业务导入事务回滚。导入后若 Git 数据与现有项目的时间重叠，请按需重算受影响日期的估算工时。
- 备份包含明文业务数据，请妥善保管；不包含 API Key、提醒去重状态、本机仓库路径或作者匹配配置。新导入项目需重新绑定本地仓库；覆盖已有项目时保留其本机绑定。

完整工作库备份包含 Git 本机绑定与历史同步记录（业务导出**不包含**这些），通过命令行维护命令执行，基于 SQLite 在线备份取得一致快照。执行前先从托盘退出应用，否则命令会提示应用已在运行并退出；路径按实际安装目录替换：

```powershell
# 备份
& "$env:LOCALAPPDATA\Programs\WeeklyReport\WeeklyReport.App.exe" --backup-work-library "D:\周报备份\weekly-report.wrbak"
# 恢复（会弹窗确认）
& "$env:LOCALAPPDATA\Programs\WeeklyReport\WeeklyReport.App.exe" --restore-work-library "D:\周报备份\weekly-report.wrbak"
```

恢复时需同时关闭其他访问该数据库的工具，且当前工作库必须已存在（新机器先启动一次应用创建空库）。恢复前会校验备份，并把当前库另存为同目录的 `weekly-report.db.pre-restore-*.bak`；恢复失败时报错并给出该副本路径。

应用配置、凭据与提醒状态存放在 `%LOCALAPPDATA%\WeeklyReport` 下的独立文件中，需单独复制。请定期把备份保存在独立位置；请勿把本机磁盘当作异地备份。更多细节见《[SQLite 单机切换指南](./docs/SQLite单机切换指南.md)》§4。

## 构建、发布和测试

日常构建与测试（无需真实数据库）：

```powershell
dotnet restore WeeklyReport.slnx
dotnet build WeeklyReport.slnx --no-restore
dotnet test WeeklyReport.slnx --no-restore
dotnet run --project src\WeeklyReport.App\WeeklyReport.App.csproj
```

发布与打包：

```powershell
# 锁定文件与 win-x64 不一致时（publish 报 NU1004）先执行一次带 RID 的还原
dotnet restore WeeklyReport.slnx -r win-x64 --force-evaluate
dotnet publish src\WeeklyReport.App\WeeklyReport.App.csproj -c Release -r win-x64 --self-contained true -p:RestoreLockedMode=true -o artifacts\publish\win-x64
ISCC.exe installer\WeeklyReport.iss
```

说明：

- 锁定文件的 RID 记录双向敏感：带 `-p:RestoreLockedMode=true` 发布需要带 `win-x64` 记录的 `packages.lock.json`，不带 RID 的 `dotnet restore --locked-mode` 则需要不带 RID 的，不匹配都会报 NU1004。普通 `dotnet restore` 在两种状态下都不报错，但可能改写 Application、Domain、Infrastructure 的锁定文件，提交前请留意。需要切回不带 RID 时执行 `dotnet restore WeeklyReport.slnx --force-evaluate`。
- 最后一条命令需要 Inno Setup 6；安装包生成在 `artifacts\installer`。升级前请从托盘退出应用并保存编辑内容：安装器准备阶段会强制结束仍在运行的应用，并静默卸载旧版本。升级安装会沿用之前选择的安装目录，新机器首次安装默认使用 `%LOCALAPPDATA%\Programs\WeeklyReport`。

MySQL 集成测试默认跳过；这些测试覆盖**保留但停用**的同步代码（`SqliteSyncApplier` / `SqliteSyncCoordinator` 等，应用运行路径不调用），用于未来重新启用同步时保持其正确性。启用前需准备名称以 `weeklyreport_test_` 开头的独立本机测试数据库，并通过本机凭据对话框输入账号和密码：

```powershell
.\scripts\test-mysql.ps1 -Database weeklyreport_test_local
```

测试脚本不会创建或删除数据库，仅清理自身创建的记录，并在结束后恢复连接环境变量；不要将连接字符串或密码写入源码、日志或版本库。

已知问题：SQLite 集成测试目前偶发失败，2026-11-09 的 12–15 次运行中有 5 次失败，每次 1–2 个用例且用例不固定。已查看详情的失败都发生在测试结束删除临时库文件时（文件被占用），根因尚未确认。

## 卸载与故障排查

卸载前从托盘退出。卸载器尝试清理本应用的系统通知注册和指向当前安装路径的自启动项；清理失败会提示，静默卸载时可查看卸载日志。卸载保留 `%LOCALAPPDATA%\WeeklyReport` 下的 SQLite 工作库与配置、受保护密钥、提醒状态及日志（若机器上仍有旧版遗留的 MySQL 数据库，也同样保留）；确认备份后可由用户自行删除不再需要的数据。

常见问题：

- **启动报“本地 SQLite 工作库不可用”**：库文件可能损坏或不可读写。本版本不会覆盖或重建该文件——先在独立位置备份该文件，再按《[SQLite 单机切换指南](./docs/SQLite单机切换指南.md)》处理。
- **启动报“尚未建立本地 SQLite 工作库”**：此前可能使用过 MySQL 版本且未迁移，或无法读取旧配置。按切换指南在旧版本完成镜像迁移，或确认后建立空白工作库。
- **启动报“尚未完成初始化”或“本地优先此前已被停用”**：前者可能是迁移中断，后者表示权威数据仍在 MySQL。两种情况应用都会退出且不改动数据，按切换指南回旧版本处理。
- **通知不显示**：检查 Windows 通知权限、勿扰模式及应用是否仍在运行。
- **Git 同步无结果**：确认 `git` 在 `PATH` 中、仓库路径与作者匹配配置正确；只读取所选仓库当前 `HEAD` 的提交。
- **DeepSeek 失败**：检查密钥、模型、网络与账户额度。

日志位于 `%LOCALAPPDATA%\WeeklyReport\logs`，不应包含密码、API Key 或周报正文。
